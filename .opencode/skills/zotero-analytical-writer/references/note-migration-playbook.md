# Note migration playbook（默认工作习惯）

这不是可选项，而是 ResearchVault 笔记迁移的默认执行方式。新会话接手时先读本文件，再动笔。

## 0. 总原则

1. **读全文，不读摘要**：动笔前必须读对应 Fulltext 的方法、实现/训练、结果、消融、局限章节；旧笔记只用于身份、frontmatter、已有引文和其他章节，**不能把旧方法段当事实来源**。
2. **不以“笔记存在”判断完成**：有 Note、有 `## 三、方法详解` 标题都不算完成；以方法段内容、配图、公式、引文和验收脚本为准。
3. **旧笔记只改方法段**：替换 `## 方法` / `## 研究方法` 为 `## 三、方法详解`，其余章节逐字保留；不整篇推倒、不重命名贡献/结果/判断章节。
4. **事实、作者解释、我们的推断分开**：原文事实用陈述句；作者解释标“作者解释”；我们的迁移判断标“推断/非原文”。原文没报告就写“论文未给”，不猜。
5. **先备份，后删除**：删除旧页、旧索引、旧模板前先复制到临时备份目录；报告里写清备份路径。
6. **不擅自 commit**：所有改动留在工作区；只有用户明确要求才 git commit。

## 1. 批次盘点（先看全局）

扫描 `02vault/**/*.md`，排除中文全译，逐篇记录：

- `zotero_key`、`fulltext_path`、`collection`；
- 方法段标题与字符数（`## 三、方法详解` / `## 方法` / `## 研究方法`）；
- 图片数、`$$` 公式块数、是否有 `引文核验`、YAML 是否可解析；
- 分类：`FULL` ≥4,500；`BORDER` 4,000–4,500；`PENDING` <4,000。

先按主题分组，再决定批次；不要按文件名顺序无脑重写。推荐批次：VOS 经典线 → 检测器/跟踪基础 → 卫星 MOT → SAM 适配 → RS/VIS。

可直接用本 skill 的扫描脚本：

```powershell
python .opencode/skills/zotero-analytical-writer/scripts/scan_note_quality.py `
  --vault "{{VAULT_ROOT}}" --json note_scan.json
```

退出码 1 表示存在硬性失败（缺方法段、旧方法标题、重复标题、图片缺失、空 fulltext_path）。

## 2. 单篇流程

1. **读身份**：frontmatter、`fulltext_path`、现有非方法章节；确认 `zotero_key` 是否存在。
2. **读全文**：先看 Fulltext 的章节标题，定位 Method / Implementation / Training / Experiments / Ablation / Limitation；按行范围读，不整篇泛读。
3. **写方法段**：按“问题 → 数据流（文字图）→ 逐模块机制 → 训练/推理配置 → 主结果/消融/反常 → 边界”组织；公式保留原文编号，训练缺项写“论文未给”。
4. **原位替换**：用正则按 `## 方法` / `## 研究方法` 到下一个 `## ` 的区间替换；替换后检查前后缀（frontmatter 和其他章节）未变，不能出现第二个方法标题。
5. **配图**：从 `03fulltext/<collection>/images/<key>/` 选 4 张左右（架构/数据/主结果/定性或消融）；相对路径 `../../03fulltext/...`；逐条确认文件存在。原文不足 4 张就全嵌入并注明“原文仅 n 图，未凑数”；图注写“这张图说明什么”，不要只写 Figure 3。
6. **引文核验**：加 `#### 引文核验`，至少 3 条逐字英文引文 + “PDF 页码未验证”；引文先在 Fulltext 里 grep，不用中文摘要反推英文。OCR 连写/空格/LaTeX 排版差异按原文照录并注明。
7. **自检**：方法段长度、公式数、训练细节、图片数、引文命中、YAML、双向链接。

可参考已达标样例：`02vault/VOS/Putting the Object Back into Video Object Segmentation.md`（Cutie，对象级记忆读取）、`02vault/MOT/Selective Mask Propagation for Multi-Object Tracking.md`（SMP，按需调度 VOS）、`02vault/MOT/Detecting Object Tracking Failure via Sequential Hypothesis Testing.md`（序贯检验）。它们展示了本 playbook 的密度、公式解释、反常结果与边界写法。

## 3. 批量验收（必须跑）

直接运行 `scripts/scan_note_quality.py --vault "{{VAULT_ROOT}}"`；硬性失败项：

- 方法段 <4,500（短论文 <4,000 且未注明“原文较短”）；
- 图片路径缺失，或图片 <4 且未注明原文不足；
- 有公式但 <2 个原文公式且未注明“原文无公式/仅 1 式”；
- 缺少 `引文核验` 节；
- `引文核验` 表/清单内英文引文 grep 未命中；
- YAML 解析失败；
- 残留 `## 方法` / `## 研究方法`；
- 重复 `## 三、方法详解`。

软性提醒（写进状态页，不阻塞）：

- `zotero_key` 为空（Vault-only 条目，需补 Zotero 身份）；
- 正文内联引文的 OCR/LaTeX 差异（正式证据以 `引文核验` 节为准）。

## 4. 索引与日志（批次完成后立即做）

- `02vault/_index/文献索引.md`：维护 `方法段` 列，值只能是 `FULL` / `BORDER` / `PENDING`；`状态` 列仍表示入库链路，不要混用。
- `02vault/_index/笔记重写状态.md`：由扫描脚本生成；总览 + 未达标清单 + 提醒；旧迁移索引删除前备份。
- `01knowledge/log.md`：追加本批次范围、重写篇数、验收结果、遗留项。
- 不要把“已生成状态页”当成“笔记已达标”；状态页必须由实际扫描结果生成。

## 5. 常见坑

- **旧笔记方法段是旧结论**：不能因为旧笔记有公式/表格就直接搬；所有数字回 Fulltext。
- **OCR 差异**：`MP<sup>2</sup>Net`、`$L_{occ}$`、`J &F`、`state-of-theart` 等不是新事实；按原文照录并注明，不要悄悄“修正”成看起来更顺的写法。
- **图片图注错位**：按 Fulltext 中 `![](...)` 的出现顺序和图注映射，不按文件名猜。
- **重复标题**：旧笔记可能已有 `## 三、方法详解`，替换区间时先检查，避免叠加。
- **并发写入**：多个批次不要同时改同一文件；发现内容被覆盖，先比对 mtime/内容，再从备份恢复，不要把别人的批次结果当自己的。
- **并行批次**：可以并行处理不同主题的笔记，但每个批次必须写不同文件；同一篇笔记只能有一个写入者。
- **报告不等于验收**：子代理或批次的“已完成”报告不能替代本地扫描；每个批次返回后必须独立跑一次 `scan_note_quality.py`，并抽查 1–2 篇的方法段内容与引文是否真的来自 Fulltext。
- **空 `zotero_key`**：只报告，不伪造；需要先在 Zotero 建条目。

## 6. 完成判定

同时满足才算完成：

1. 目标笔记全部 `FULL`；
2. 硬性失败项为 0；
3. 图片/公式/训练细节/边界齐全；
4. `引文核验` 可 grep；
5. `文献索引` 方法段列与 `笔记重写状态` 已更新；
6. `log.md` 已追加；
7. 备份路径已记录，未擅自 commit。
